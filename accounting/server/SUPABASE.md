# Supabase バックエンドのセットアップ（ログイン認証つき・推奨）

自前サーバーを動かさずに、**Supabase（マネージドPostgres＋Auth）** で
クラウド同期・ログイン保護・複数人共有を行う手順です。所要 約10分。

## 1. Supabase プロジェクトを作成
1. https://supabase.com にサインアップ → **New project** を作成（リージョンは東京=Tokyo推奨）。
2. 作成後、**Project Settings → API** を開き、次の2つを控える：
   - **Project URL**（例 `https://xxxx.supabase.co`）
   - **anon public** キー（公開用。ブラウザに置いてOK）

## 2. テーブルと権限（RLS）を作成
1. 左メニュー **SQL Editor** → **New query**。
2. リポジトリの `server/supabase.sql` の内容を貼り付けて **Run**。
   - 台帳（`ledgers`）・メンバー（`ledger_members`）・RLS・作成/招待用の関数が作られます。

## 3. メール認証の方針
- **Authentication → Providers → Email** を有効化。
- 社内少人数ですぐ使い始めたい場合：**Authentication → Settings** で
  「Confirm email」をオフにすると、登録後すぐサインインできます。
  （本番運用でセキュリティを高めたい場合はオンのままメール確認を使ってください）

## 4. 会計アプリ側の設定
1. アプリを開き、**設定 → クラウド（Supabase）** に、2で控えた **Project URL** と **anon key** を入力。
2. **「サインイン / 台帳を選ぶ」** をクリック → メール・パスワードで**新規登録**（または**サインイン**）。
3. 初回は **新規台帳を作成**（例：合同会社アイズ）。現在のローカルデータがそのままクラウドへ保存されます。
4. 以後、アプリ起動時に自動で最新を取得、保存時にクラウドへ反映されます。

## 5. 複数人で共有する
- 共有したい相手にも、同じアプリで**新規登録**してもらう（メール＋パスワード）。
- 台帳の所有者が **設定 → クラウド（Supabase）→ メンバーを招待** に相手のメールを入れて **招待**。
- 相手はサインイン後、その台帳を選んで同じ帳簿を編集できます（RLSで、許可されたメンバーだけがアクセス可能）。

## セキュリティのポイント
- anon キーは公開前提ですが、**RLS（行レベルセキュリティ）** により、
  ログインして許可された台帳メンバーしかデータにアクセスできません。
- 端末のログイン情報（トークン）はそのブラウザ内のみに保存されます。

## 自動化（コネクタ）について
- Gmail取込・在庫/AI監視・月次レポート等の自動コネクタは、現状は自前同期サーバーから
  データを取得します。Supabaseから直接読むようにする場合は **service_role キー**（サーバー専用・非公開）
  を使う構成が必要です。ご希望があればコネクタのSupabase対応も追加します。

## セキュリティ強化（この構成で有効）
- **RLS（行レベルセキュリティ）**：ログインして許可された台帳メンバーだけが読み書き可能。
- **権限分離**：メンバーの招待・削除・台帳削除は**オーナーのみ**。メンバー表への直接操作は既定で拒否（RPC経由のみ）。
- **CSP（コンテンツセキュリティポリシー）**：外部スクリプトを禁止しXSSを抑止（アプリに内蔵）。
- **セッション保護**：共有PC向けの「ログインを保持しない」設定、**無操作で自動ログアウト**（既定30分）、トークンの定期更新。
- 推奨：本番では Supabase の「Confirm email」をオン、強いパスワード、必要なら2要素認証（Supabase側設定）。
- 静的ホスティングでHTTPヘッダも付けたい場合は Netlify/Cloudflare 等の `_headers` で
  `Strict-Transport-Security` / `X-Frame-Options` / `X-Content-Type-Options` を付与できます（GitHub Pagesはmeta CSPで代替）。
