## 2. 仕組み（実装時の設計）

### テーマ設定オブジェクト（1つ）
```ts
type BrandTheme = {
  key: 'allmighty' | 'automotive';
  productName: string;          // 製品名
  logo: string;                 // ロゴ
  colors: { primary; base; accent; ... };  // 配色トークン
  defaultTemplates: string[];   // 初期で見せる業種テンプレ
  lp: { hero; subcopy; features[]; useCases[] };  // LP文言
};
```
- `allmighty`：全業種テンプレ、中立コピー
- `automotive`：`defaultTemplates = car_sales / car_maintenance / car_bodyshop / car_buyout / car_dealer`、車向けコピー

### 切替方法
- **ドメイン判定**で自動選択（`car.*`→automotive、それ以外→allmighty）
- フォールバックは環境変数／テナントの業種から選択

### 管理画面（ログイン後）
- 画面構造は**共通**。テーマ（配色・ロゴ・製品名）と初期テンプレだけ差し替え
- **中立化が必要な箇所**（現状、車前提の文言がハードコード）：
  - AI応対テストの例文（`frontend/app/(app)/ai-test/page.tsx` の OPENING）
  - 入力欄プレースホルダ（「車種・年式」等）
  - デモ初期データ（`backend/src/demo/fixtures.ts` の会社名・挨拶・受付種別）
  - → これらを「テーマ由来 or テナントデータ由来」に置換し、業種非依存にする

### 集客LP
- LPコンポーネントを**2セット**（汎用／自動車）用意し、**同じ申し込み導線・同じAPI**に誘導
- 自動車LPは上記「④用途」をヒーロー＆機能セクションの中心に
