## 2. 技術構成（API-first・将来ネイティブ前提）

| レイヤー | 採用 | 役割 |
|---------|------|------|
| フロント(今) | Next.js 16 (App Router) + TypeScript + Tailwind v4 | Web/PWA |
| フロント(将来) | React Native 想定 | 同じSupabaseを使い回す |
| 認証 | Supabase Auth | メール/PW＋LINE Login（段階） |
| DB | Supabase(PostgreSQL) | RLSで権限をDB層でも担保 |
| 画像 | Supabase Storage | 投稿・アバター・スキル画像 |
| 波情報 | **Open-Meteo Marine/Forecast API** | 無料・キー不要。波高/周期/向き/水温＋天気/風/降水/日の出入り |
| 決済(将来) | Stripe 等 PSP | カード情報を自社保持しない |

**設計原則**：権限は UI＋API＋RLS の三重化。ロジックはバック寄せ。収益機能は“仕込み”のみ。

## 3. 会員モデル（2軸）

会員 = **種別(role)** × **プラン(plan)**。混ぜない。

| 種別 | 役割 | 権限 |
|------|------|------|
| Visitor | 閲覧中心(ゲスト) | 一部閲覧のみ |
| Beginner | 質問・体験共有 | 投稿/いいね/コメント/スキル申込 |
| Local | 波情報・ローカル知見 | ＋waves投稿・信頼バッジ |
| Staff/Admin | 運営 | 全権＋管理画面 |

| プラン | 今(MVP) | 将来の特典(例) |
|--------|---------|----------------|
| free | 全機能使える | 波情報=当日まで／広告あり |
| premium | （未提供） | いい波プッシュ＋7日予報／優先予約／スキル手数料割引／現地特典 |

## 4. 画面構成（実装済み）

- **公開**：`/`（ホーム）/ `/community`（フィード・ゲストぼかし）/ `/community/posts/[id]`（詳細・いいね・コメント・通報）/ `/community/new`（投稿）/ `/waves`（天気×波＋ローカルの声）/ `/skills`（一覧）/ `/skills/[id]`（詳細）/ `/skills/[id]/apply`（申込）/ `/skills/new`（出品）
- **認証**：`/login` `/signup` `/password/reset` `/auth/callback`
- **マイ**：`/me` `/me/edit` `/me/posts` `/me/skills`
- **運営**：`/admin/login` `/admin`（ダッシュボード）`/admin/posts` `/admin/members` `/admin/reports`

カテゴリ：`waves / experiences / questions / events / gear`
スキル分類：`school / repair / photo / guide / other`

## 5. データベース（実装済みマイグレーション）

- `0001` members（role×plan・RLS・登録時自動作成・is_staff()/current_member_role()）
- `0002` posts / comments / likes（like_count自動更新・wavesはlocal以上）
- `0003` skills / skill_applications（自分の出品には申込不可・決済用order_id/price仕込み）
- `0004` reports / admin_audit_logs（staff限定）
- `schema.sql` … 上記4本の統合（Supabase SQL Editorに一括貼付用）

将来（仕込みのみ）：`skill_orders`（手数料）/ `ad_banners`（広告）/ `subscriptions`（有料会員）

## 7. 法務（決済が動く時）

必須表示：価格 / 送料 / 追加費用 / 支払方法と時期 / 引渡時期 / 返品・キャンセル / 事業者情報 / 問い合わせ先。
無在庫を誤解させない・即納表現禁止（納期は具体）・返品条件は見つけやすく・カード情報は自社保持しない(PSP)。
スキルは当面「連絡・相談まで無料」、価格は「応相談」ベースで断定表現を回避。

## 9. 引き継ぎ・開発前提

1. 既存構想の延長で進化（作り変えない）。世界観・導線・運用思想・法務を維持。
2. 権限は UI＋API＋RLS の三重化。会員は 種別×プラン の2軸。
3. API-firstでロジックをバック寄せ、将来ネイティブが同じ中身を使える形に。
4. 収益機能は“仕込み”を先に：テーブル/フラグだけ用意し、課金処理は後で差す。
5. 一般ユーザーからは取らない（関係人口化）。取るのはスキル利用・広告・有料会員のみ。
6. 波情報＝Open-Meteo(客観)＋ローカル投稿(主観)の二段構成。
