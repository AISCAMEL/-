# バイモダイレクト 公開（デプロイ）手順書

このサイトは**静的サイト（HTML/CSS/JS）**なので、無料の静的ホスティングにそのまま公開できます。
申込の自動化（スプレッドシート登録・LINE通知・AI要約）は **GAS（Google Apps Script）** を別途デプロイして接続します。

---

## 0. 全体像
```
[公開サイト（site/）] ──申込──▶ [GAS Web App] ──▶ スプレッドシート登録 / LINE通知 / AI要約
   Netlify / Cloudflare Pages / GitHub Pages 等         （gas/ をデプロイ）
```
購入のやりとりは外部「車ひろば エージェント」（agent.car-hiroba.jp）を利用。

---

## A. サイトを公開する（いずれか1つ）

### A-1. Netlify（ドラッグ&ドロップが最速）
1. https://app.netlify.com/ に登録・ログイン
2. 「Add new site」→「Deploy manually」
3. `site/` フォルダを**そのままドラッグ&ドロップ**
4. 発行されたURL（例 `https://xxxx.netlify.app`）で即公開。独自ドメインは「Domain settings」から設定。

### A-2. Cloudflare Pages（GitHub連携）
1. このリポジトリ（`aiscamel/-`）をCloudflare Pagesに接続
2. ビルド設定：**ビルドコマンドなし**／**出力ディレクトリ = `site`**
3. デプロイ → 発行URLで公開。

### A-3. GitHub Pages
1. リポジトリ Settings → Pages
2. Source：対象ブランチ ／ フォルダ `/site`（※Pagesはサブフォルダ指定可。不可なら `site/` の中身をルートに置くか `docs/` 運用）
3. 公開URL：`https://aiscamel.github.io/-/`

> いずれも `index.html` が入口。`sell.html` `shipping.html` `mypage.html` `login.html` `manual.html` `privacy.html` も同階層に揃っています。

## B. 申込の自動化（GAS）を接続する ＝ 実行ガイド

> 所要 約20分。クリック順どおりに進めれば動きます。詳細版は `gas/セットアップ手順.md`。

### B-1. プロジェクト作成とコード貼り付け
1. https://script.google.com/ →「新しいプロジェクト」。
2. 既定の `コード.gs` を消し、`gas/` の各ファイルを**ファイル単位で**追加・貼り付け：
   `Config.gs` / `Setup.gs` / `WebApp.gs` / `Line.gs` / `Slack.gs` / `AI.gs`。
3. 💾 保存。

### B-2. 設定（`Config.gs`）
| キー | 用途 | 必須 |
|---|---|---|
| `SPREADSHEET_ID` | データ保存先。空なら `setupAll` が自動作成 | 任意 |
| `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_STAFF_IDS` | LINE通知 | 任意 |
| `SLACK_WEBHOOK_URL` | Slack通知（Incoming Webhook） | 任意 |
| `SLACK_SLASH_TOKEN` | Slackから `/相場回答` 等を使う場合 | 任意 |
| `OPENROUTER_API_KEY` | 申込のAI要約・優先度づけ | 任意 |
| `SELL_SHEET_PDF_FOLDER_ID` | 出品票・オリコ申込書PDFの保存フォルダ | 任意 |

### B-3. シート作成 → 公開
4. 関数プルダウンで **`setupAll`** を選び「実行」→ 初回は権限を「許可」。
   → 6シート（オーダー管理／出品管理／ローン審査／会員マスタ／問い合わせ／相場見積り）が自動作成。
5. 「デプロイ」→「新しいデプロイ」→ 種類「**ウェブアプリ**」／実行ユーザー「**自分**」／アクセス「**全員**」→ デプロイ。
6. 発行された**ウェブアプリURL（`.../exec`）**をコピー。

### B-4. LPと接続
7. `site/assets/js/app.js` 先頭の `ENDPOINT` に貼り付けて再公開：
   ```js
   var ENDPOINT = "https://script.google.com/macros/s/XXXX/exec";
   ```
   → 会員登録・購入オーダー・出品申込・ローン仮申込・相場見積り・お問い合わせが、
   自動でシート登録＋LINE/Slack通知＋（出品票/オリコ申込書）PDF生成されます。

### B-5. 動作確認（接続できたかのチェック）
- LPで会員登録 → **会員マスタ**シートに行が増える。
- 購入オーダー送信 → **オーダー管理**に行が増え、LINE/Slackに通知が届く。
- ローン仮申込 → 入力メール宛に**オリコ申込書PDF**が届く。
- Slackで `/相場回答 QT-xxxx 金額` → **相場見積り**シートが「回答済み」、マイページに反映。

> ⚠️ コードを直したら反映には再デプロイが必要：
> 「デプロイ」→「デプロイを管理」→ ✏️ →「バージョン＝新しいバージョン」→ 保存（URLは不変）。

# F. 加盟店ポータル（社外秘・サーバー版）を公開する ＝ 実行ガイド

加盟店ポータル `/partner/` と本部コンソール `/admin/` は**社外秘**です。URLを知られても見られないよう、**サーバー側でログイン認証**して守ります（`server/server.js`）。パスワードや保存データはサーバーのディスクに残るため、**「永続ディスク」が使えるホスティング**が必須です。

> ⚠️ **Netlify / Cloudflare Pages / GitHub Pages（＝A章の静的ホスティング）はここでは使えません。**
> あれらは「ファイルを置くだけ」でサーバーが常駐せず、ログインやデータ保存ができないためです。
> A章の一般公開サイトはあのままでOK。社外秘ポータルだけ、この F 章の常駐サーバーで動かします。

## F-0. どれを選ぶ？

| 方法 | 難易度 | 月額目安 | 向いている人 |
|---|---|---|---|
| **F-1. Render（推奨）** | ★☆☆ ブラウザ操作中心 | 約 $7〜 | まず確実に立ち上げたい。サーバー管理はしたくない |
| **F-2. VPS + Docker** | ★★☆ SSHが要る | 約 ¥1,000〜 | 自分で自由に触りたい・費用を抑えたい |
| **F-3. Vercel（注意）** | ★☆☆ | 無料〜 | 一般公開サイトの即公開向け。※社外秘ポータルは要改修 |

## F-1. Render で公開（推奨・ワンクリックに近い）

リポジトリ直下に **`render.yaml`**（設定ファイル）を用意済みなので、ほぼ自動です。

1. このリポジトリを自分の GitHub アカウントに置く（Fork でもコピーでも可）。
2. https://render.com にサインアップ（GitHub連携）。
3. ダッシュボードで **「New +」→「Blueprint」** を選び、このリポジトリを指定。
4. `render.yaml` が読み込まれ、以下が**自動で**作成される：
   - Web サービス（Docker で `server/server.js` を起動）
   - 永続ディスク 1GB（`/var/bmd-data` にマウント）
   - `BMD_SECRET`（セッション署名鍵）を**自動生成**
5. 「Apply」でデプロイ開始。数分で `https://bmd-portal-xxxx.onrender.com` のようなURLが発行される。
6. 発行URLで動作確認：
   - `/partner/login.html` → `BMD-001 / bmd-demo-2026` でログイン
   - `/admin/login.html` → `HQ-ADMIN / admin-demo-2026` でログイン
7. **公開前に必ず**（F-4 参照）：本部コンソールでデモのパスワードを変更し、デモ加盟店を停止。

> HTTPS は Render が自動で付きます（`X-Forwarded-Proto: https` も渡るので Cookie は自動的に Secure になります）。
> 独自ドメインは Render の「Settings → Custom Domains」から設定。
> 無料プランは永続ディスク非対応・スリープするため、**starter 以上**が必要（`render.yaml` に設定済み）。

## F-2. VPS + Docker で公開（費用重視・自由度重視）

ConoHa / さくらの VPS / Xserver VPS / AWS Lightsail などに SSH してコンテナで常駐させます。Docker 一式（`Dockerfile` / `docker-compose.yml`）は用意済みです。

```bash
# サーバーに SSH した後
git clone <このリポジトリのURL> bmd && cd bmd

# 秘密鍵を生成して起動（データはホストの ./server に永続化される）
BMD_SECRET="$(openssl rand -hex 32)" docker compose up -d --build
# → http://<サーバーIP>:8080
```

**HTTPS 化（本番必須）**：前段に Caddy を置くのが最も簡単です。ドメインを VPS に向けたうえで：

```caddyfile
# /etc/caddy/Caddyfile
portal.example.com {
    reverse_proxy localhost:8080
}
```
Caddy が Let's Encrypt 証明書を自動取得し、`X-Forwarded-Proto: https` も渡すので Cookie が Secure になります。

- 停止：`docker compose down` ／ 更新：`git pull && docker compose up -d --build`
- アカウント追加は本部コンソール、または
  `docker compose exec bmd node server/add-partner.js BMD-002 郡山店 <PW>`

## F-3. Vercel の注意点（今すぐ公開できるが制約あり）

Vercel は**サーバーレス**（リクエストごとに使い捨て環境）で、ファイル書き込みが残りません。
そのため**この社外秘ポータルは、ログインや保存機能がそのままでは動きません**（`partners.json` や `records.json` が保存できない）。

- **一般公開サイト（`site/` の LP・FAQ 等）だけ**を素早く公開する用途なら Vercel でOK。
- 社外秘ポータルまで Vercel で動かすには、アカウント・レコードの保存先を**外部DB（Vercel KV / Postgres 等）に置き換える改修**が必要です。ご希望なら対応します。
