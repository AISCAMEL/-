# カーメル書面作成システム｜クラウド連携セットアップ

`site/carmel-documents.html`（書面作成ツール）と GAS バックエンドをつなぎ、
「☁ クラウド保存」でフォーム内容を **Google スプレッドシートに記録** ＋
**スタッフへ LINE / Slack 通知** できるようにする手順です。

> **設計方針**：ツール本体は **エンドポイント未設定でもそのまま使えます**（ローカル保存）。
> クラウド連携は「あとから組み込む」形。GAS をデプロイして URL を1か所貼るだけで有効化されます。

---

## 全体像

```
carmel-documents.html            GAS ウェブアプリ                Google 各サービス
┌───────────────┐  POST(JSON)   ┌──────────────┐            ┌──────────────┐
│ ☁ クラウド保存  │ ───────────▶ │ doPost         │ ─記録────▶ │ スプレッドシート │
│ (type:cmldoc)  │  no-cors       │ handleCmlDoc_  │ ─通知────▶ │ LINE / Slack   │
└───────────────┘                └──────────────┘            └──────────────┘
```

- 送信は `no-cors` + `text/plain`（プリフライト回避）の **fire-and-forget**。
- 9 種すべての書面を **1 枚のシート**「カーメル書面」に記録（明細は JSON 列）。

---

## 手順

### 1. GAS プロジェクトに追加
`gas/` を Google Apps Script プロジェクトへ反映（`clasp push` もしくは手動コピー）。
最低限、次のファイルが同一プロジェクトにあること：

- `CarmelDocs.gs`（本機能の受け口）
- `Config.gs` / `WebApp.gs` / `Setup.gs` / `Line.gs`（共通基盤）

### 2. 受け口の「組み込み」（このリポジトリでは対応済み）
`WebApp.gs` の `doPost` 内 `switch` に以下が入っていることを確認：

```js
case "cmldoc":  result = handleCmlDoc_(data);  break;
```

### 3. 設定
`Config.gs` の `getConfig()` を編集：

| キー | 内容 |
|---|---|
| `SPREADSHEET_ID` | 記録先スプレッドシートID（空欄なら初回に自動作成） |
| `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_STAFF_IDS` | LINE 通知（任意） |
| `SLACK_WEBHOOK_URL` | Slack 通知（任意） |
| `SHEET_CML_DOCS` | 記録シート名（既定「カーメル書面」） |

### 4. シート作成（任意）
GAS エディタで **`cmlSetup()`** を実行 → 見出し付きシートが用意されます。
（未実行でも初回受信時に自動作成されます）

### 5. デプロイ
「デプロイ」→「新しいデプロイ」→ 種類 **ウェブアプリ** →
実行ユーザー **自分** ／ アクセス **全員** → デプロイ →
表示された **ウェブアプリの URL（/exec）** をコピー。

### 6. ツールへ組み込み（1か所）
`site/carmel-documents.html` 冒頭の設定を編集：

```js
const CLOUD = {
  ENDPOINT: 'https://script.google.com/macros/s/XXXXX/exec',  // ← 貼り付け
  get ENABLED(){ return !!this.ENDPOINT; },
};
```

保存して再デプロイすれば、ヘッダーのバッジが **「☁ クラウド接続」** になり、
「💾 保存」時に自動でクラウド送信されます（保存済み一覧に送信ステータス列・☁再送ボタンが表示）。

### 7. 動作確認
- GAS 側：`cmlTest()` を実行 → シートに1行追加＆通知が来ればOK。
- ツール側：氏名を入れて「💾 保存」→ トーストが「✅ 保存＋クラウド送信 完了」。

## 記録シートの列

| 列 | 内容 |
|---|---|
| 受信日時 | サーバー受信時刻 |
| 書面ID | `CML-1001`… の連番 |
| 書面タイプ | 例）自動車売買契約書 |
| 書面種別コード | `d1`〜`d9` |
| お客様氏名 / 書類番号 / 担当者 / 作成日 | 主要項目（`_name`/`_no`/`_staff`/`_date` から自動抽出） |
| 端末保存日時 | ツール側の保存時刻 |
| 明細(JSON) | 全入力項目（`{ "d1_car": "…", … }`） |

> 明細を列展開したい場合は、書面種別ごとにシートを分ける／`JSON.parse` で
> 展開する GAS を追加できます（将来拡張）。

## トラブルシュート

- **シートに記録されない**：GAS のデプロイが「全員アクセス」か、`ENDPOINT` の
  `/exec` URL が正しいか確認。`no-cors` のため画面側では成否が取れません（＝
  ステータスは「未送信/送信済」の見た目上の記録）。実記録は必ずシートで確認。
- **通知が来ない**：`LINE_STAFF_IDS`（userId）または `SLACK_WEBHOOK_URL` を確認。
- **CORS エラーが出る**：本ツールは `no-cors` 送信のため通常発生しません。独自に
  レスポンスを読む実装へ変える場合は GAS 側 CORS 対応が別途必要です。

## スタッフログイン（正式・GASアカウント認証）

書面ツールは `AUTHZ.MODE='account'` で **スタッフ個別アカウント（ID＋パスワード）**
ログインになります（認証は `gas/Auth.gs`、既存サイトと同じJSONP方式）。

### 準備
1. `gas/` を GAS にデプロイ（`Auth.gs` / `WebApp.gs` 含む・同一プロジェクト）。
2. GASエディタでスタッフを作成：
   ```js
   createUser('sato@carmel.jp', '強いパスワード', 'hq', '佐藤');
   ```
   （役割 role は `hq`＝本部/全権 か `partner` 等。パスワードはSHA-256ハッシュ保存）
3. ウェブアプリの `/exec` URL を `carmel-documents.html` の `CLOUD.ENDPOINT`
   （または `AUTHZ.ENDPOINT`）へ設定。

### 動作
- 起動時に ID＋パスワードを要求 → GAS `Auth.gs` が認証しセッショントークン発行。
- ヘッダーに **ログイン中スタッフ名**を表示。「🚪 ログアウト」でセッション破棄。
- 保存／クラウド送信時、**作成者（ログインユーザー）**を記録シートの
  「作成者(ログイン)」列に残します（誰が作成したか追跡可）。
- `ENDPOINT` 未設定時は **デモログイン**（任意IDで入れる／後から接続）。

### モード切替
- `AUTHZ.MODE='passcode'` … 共有パスコード（簡易）
- `AUTHZ.MODE='off'` … 認証なし
- セキュリティ注意：JSONP方式のためPWがURL/サーバーログに残り得ます
  （`gas/Auth.gs` 冒頭・`docs/BUYMO_認証設計.md` の本番ハードニング参照）。

## （任意）マネーフォワード クラウド契約 連携（雛形）

契約系書面（既定 `d1`/`d4`/`d6`）を **電子契約（MFクラウド契約）へ連携**するための
枠組みを `gas/MoneyForward.gs` に用意しています。**認証情報とエンドポイントを
後から差し込むだけ**の後付け設計です。

> **前提（正直に）**：実際に動かすには ①MFクラウド契約の法人プラン、
> ②MF開発者コンソールでのアプリ登録／API利用申請（OAuth2 or APIキー）、
> ③公式仕様に基づく正式エンドポイントの設定 が必要です。オープンな公開APIでは
> ありません。MF公式：https://developers.biz.moneyforward.com/docs/

### 有効化手順
1. `Config.gs` の `MF_ENABLED` を `"1"` に。
2. 認証方式に応じて設定：
   - **OAuth2**：`MF_TOKEN_URL` / `MF_CLIENT_ID` / `MF_CLIENT_SECRET`（必要なら `MF_SCOPE` / `MF_REFRESH_TOKEN`）
   - **APIキー**：`MF_AUTH_TYPE="apikey"` ＋ `MF_API_KEY`
3. `MF_API_BASE` と各エンドポイント（`MF_EP_CREATE_CONTRACT` 等）を**公式仕様で確認して設定**。
4. `MF_CONTRACT_DOCTYPES` で電子契約に回す書面種別を調整（既定 `d1,d4,d6`）。
5. `mfPing()`（トークン取得確認）→ `mfTestCreate()`（サンプル契約作成）で動作確認。

### 動作
- 書面受信（`handleCmlDoc_`）時、対象種別なら `mfForwardIfEligible_()` が自動実行。
- 結果は記録シートの **「MF連携」「MF契約ID」** 列に記録され、成功時はスタッフへ通知。
- 未設定・非対象種別・OFF のときは何もしません（通常記録のみ）。

### 実装で"埋める"箇所（★）
`gas/MoneyForward.gs` 内のコメント `★要設定★` `★要マッピング調整★`：
- トークン発行URL・スコープ（`mfGetToken_`）
- 契約作成エンドポイントとレスポンスのID取り出し（`mfCreateContract_`）
- 書面フィールド → MF契約リクエストの項目対応（`mfBuildContractRequest_`）

> これらは MF の製品仕様に依存するため、公式ドキュメントの正式スキーマに
> 合わせて確定してください（本雛形は推測値を入れていません）。
