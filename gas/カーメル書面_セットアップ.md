# カーメル書面作成システム｜クラウド連携セットアップ

`site/carmel-documents.html`（書面作成ツール）と GAS バックエンドをつなぎ、
「☁ クラウド保存」でフォーム内容を **Google スプレッドシートに記録** ＋
**スタッフへ LINE / Slack 通知** できるようにする手順です。

> **設計方針**：ツール本体は **エンドポイント未設定でもそのまま使えます**（ローカル保存）。
> クラウド連携は「あとから組み込む」形。GAS をデプロイして URL を1か所貼るだけで有効化されます。

---

## 全体像

```
carmel-documents.html            GAS ウェブアプリ                Google 各サービス
┌───────────────┐  POST(JSON)   ┌──────────────┐            ┌──────────────┐
│ ☁ クラウド保存  │ ───────────▶ │ doPost         │ ─記録────▶ │ スプレッドシート │
│ (type:cmldoc)  │  no-cors       │ handleCmlDoc_  │ ─通知────▶ │ LINE / Slack   │
└───────────────┘                └──────────────┘            └──────────────┘
```

- 送信は `no-cors` + `text/plain`（プリフライト回避）の **fire-and-forget**。
- 9 種すべての書面を **1 枚のシート**「カーメル書面」に記録（明細は JSON 列）。

---

## 手順

### 1. GAS プロジェクトに追加
`gas/` を Google Apps Script プロジェクトへ反映（`clasp push` もしくは手動コピー）。
最低限、次のファイルが同一プロジェクトにあること：

- `CarmelDocs.gs`（本機能の受け口）
- `Config.gs` / `WebApp.gs` / `Setup.gs` / `Line.gs`（共通基盤）

### 2. 受け口の「組み込み」（このリポジトリでは対応済み）
`WebApp.gs` の `doPost` 内 `switch` に以下が入っていることを確認：

```js
case "cmldoc":  result = handleCmlDoc_(data);  break;
```

### 3. 設定
`Config.gs` の `getConfig()` を編集：

| キー | 内容 |
|---|---|
| `SPREADSHEET_ID` | 記録先スプレッドシートID（空欄なら初回に自動作成） |
| `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_STAFF_IDS` | LINE 通知（任意） |
| `SLACK_WEBHOOK_URL` | Slack 通知（任意） |
| `SHEET_CML_DOCS` | 記録シート名（既定「カーメル書面」） |

### 4. シート作成（任意）
GAS エディタで **`cmlSetup()`** を実行 → 見出し付きシートが用意されます。
（未実行でも初回受信時に自動作成されます）

### 5. デプロイ
「デプロイ」→「新しいデプロイ」→ 種類 **ウェブアプリ** →
実行ユーザー **自分** ／ アクセス **全員** → デプロイ →
表示された **ウェブアプリの URL（/exec）** をコピー。

### 6. ツールへ組み込み（1か所）
`site/carmel-documents.html` 冒頭の設定を編集：

```js
const CLOUD = {
  ENDPOINT: 'https://script.google.com/macros/s/XXXXX/exec',  // ← 貼り付け
  get ENABLED(){ return !!this.ENDPOINT; },
};
```

保存して再デプロイすれば、ヘッダーのバッジが **「☁ クラウド接続」** になり、
「💾 保存」時に自動でクラウド送信されます（保存済み一覧に送信ステータス列・☁再送ボタンが表示）。

### 7. 動作確認
- GAS 側：`cmlTest()` を実行 → シートに1行追加＆通知が来ればOK。
- ツール側：氏名を入れて「💾 保存」→ トーストが「✅ 保存＋クラウド送信 完了」。

## 記録シートの列

| 列 | 内容 |
|---|---|
| 受信日時 | サーバー受信時刻 |
| 書面ID | `CML-1001`… の連番 |
| 書面タイプ | 例）自動車売買契約書 |
| 書面種別コード | `d1`〜`d9` |
| お客様氏名 / 書類番号 / 担当者 / 作成日 | 主要項目（`_name`/`_no`/`_staff`/`_date` から自動抽出） |
| 端末保存日時 | ツール側の保存時刻 |
| 明細(JSON) | 全入力項目（`{ "d1_car": "…", … }`） |

> 明細を列展開したい場合は、書面種別ごとにシートを分ける／`JSON.parse` で
> 展開する GAS を追加できます（将来拡張）。

## トラブルシュート

- **シートに記録されない**：GAS のデプロイが「全員アクセス」か、`ENDPOINT` の
  `/exec` URL が正しいか確認。`no-cors` のため画面側では成否が取れません（＝
  ステータスは「未送信/送信済」の見た目上の記録）。実記録は必ずシートで確認。
- **通知が来ない**：`LINE_STAFF_IDS`（userId）または `SLACK_WEBHOOK_URL` を確認。
- **CORS エラーが出る**：本ツールは `no-cors` 送信のため通常発生しません。独自に
  レスポンスを読む実装へ変える場合は GAS 側 CORS 対応が別途必要です。
