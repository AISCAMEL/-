## 🔴 必須（公開前に運営者が対応）

| # | やること | どこで | 効果 |
|---|---|---|---|
| 1 | **Supabase を接続** | 手順書 **`docs/supabase-setup.md`** の通りに（`schema.sql` を一括実行 → 接続情報を Vercel に登録 → 再デプロイ） | ログイン・会員登録・投稿・管理画面・お問い合わせが動く。デモデータは自動で消える |
| 2 | **管理者アカウントを作る** | 会員登録後、Supabase の `members` で自分の role を staff/admin に | 管理画面（広告・投稿・お問い合わせ管理）が使える |
| 3 | **事業者情報を記入** | `web/src/lib/site.ts` の `operator`（名称・責任者・所在地・電話・メール・制定日） | 特定商取引法表記・プライバシーポリシー・利用規約に反映（いまは【要記入】表示） |
| 4 | **本番ブランチの設定** | Vercel → Project Settings → Git → Production Branch を `iwasawa-surf-demo` に（または main にマージ） | いまは push しても本番に自動反映されず、毎回手動デプロイが必要 |
| 5 | **Open-Meteo（波・天気予報）の商用利用** | https://open-meteo.com/en/pricing で API プランを契約し、キーを設定 | 無料版は **非商用** が条件。広告・有料講座があるサイトは商用にあたる可能性が高い |

## 🔵 監視（公開後）

- Vercel Hobby プランは **ログが1時間しか残らない**。継続監視は次のどれか：
  - 無料の外形監視（例：UptimeRobot）で **`/api/health`** を5分おきにチェック（おすすめ）
    - 波予報・潮位表が取れないと 503 を返すので、監視サービスから異常をメールで受け取れる
    - 返り値の `sources` で、どのデータ源（波・潮・気象庁警報）が落ちているか分かる
  - Vercel の Speed Insights / Web Analytics を有効化（アクセス数・表示速度）
  - Claude の定期タスクで、毎日「全ページ巡回＋本番エラー確認」を実行して報告
- 外部データの出典：気象庁（警報・潮位表）と Open-Meteo の出典表示は各カードに記載済み。
  気象庁の防災情報JSONは公式APIではないため、形式が変わったら表示が消える（ページは壊れない）。
